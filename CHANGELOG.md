# Changelog

What changed, newest first. Each release is also on the [releases page](https://github.com/ashirabench/branch/releases).

- [Nov 18, 2026] The whole test suite runs on Windows on every push (418 tests pass there), not only when the installers are built. The desktop app runs in UTF-8 mode, so its console never fails on a character such as −, and the output of every subprocess is read as UTF-8.
- [Nov 18, 2026] Every text file is opened as UTF-8. On Windows, a file opened without it is read in another encoding: the installer of 0.2.1 showed the source of the Brazilian glass recycling rate ("Paraná") garbled. A test of the architecture now fails on any file opened without it. The reference test of the builder compares numbers with a tolerance, because Windows computes the last digit of some quantiles differently.
- [Nov 18, 2026] A review from the side of openLCA's developers. The installers were built with Python 3.11, which installs olca-ipc 2.4, while every test and every check against openLCA ran with 2.6; they now use Python 3.13 and the versions of `constraints.txt`, and BRANCH requires Python 3.12, as olca-ipc 2.6 does. olca-ipc does not raise when openLCA fails a calculation: BRANCH now reads openLCA's message and always releases the result. A hosted page never connects to an openLCA on the server. The README and the app no longer say that openLCA's Monte Carlo simulation was run on the model sent (it was not, and with BAFU:2026 it would draw the wrong signs). Every script now says the error it catches.
- [Nov 18, 2026] No code that nothing uses: a tool (vulture) found a class, three functions and a constant that only the tests or nothing called, and they are gone; a test now fails if such code comes back. The map no longer reads the pallet and the stretch film, which no model used. `QUICK=1 bash reproduce.sh` now runs every stage on a few cases in about 4 minutes on two cores (it took 30).
- [Nov 18, 2026] A third reading, of every file, running every command the documents give. `bash reproduce.sh figures` no longer replaces the committed summaries with a folder `results/` left by an earlier, partial or QUICK run, and QUICK now reaches every experiment script; `--all-grids` writes the table the paper cites. The summary of the page names the indicator chosen, not always climate. The paper now says where value-laden choices are made (the benchmark models have none), that the ten other pairs use the nine added materials, and how many priors are assumptions in France and outside Europe. Unused code of the first prototype (`BeliefBase`) is gone.
- [Nov 18, 2026] A second reading of every document against the code and the data. The terminal demonstration now uses the setting of the application (a certificate of 2.5% and three questions per round), so it repeats the worked example; the guides name the scripts they had left out, the priors that are still assumptions and the products of the ten other pairs; the paper no longer names Docker or a count of tests.
- [Nov 18, 2026] Only what is needed stays: the Dockerfile (no test ever built it), the walkthrough notebook (demo numbers, repeating the README), the source of the proposal (its PDF stays), the scripts of past sessions in `experiments/record/` (the plans stay), the hosting guide (its rules are now in the operating guide) and the code of conduct. The usage guide keeps only what no other page says; the data guide lists only folders that exist; the paper says that the summaries of the model before the aluminium correction are those of version 0.1.2.
- [Nov 18, 2026] The architecture, with the same models and results (a file written by the earlier code proves it for the builder; the reports, what is sent to openLCA and the page were compared with the earlier code too). The function of 320 lines that built the terms of a product is now one small function per stage of the life cycle, and no function of the repository is longer than 50 lines. The installed package carries its data; one module knows where the data is; the page is separated from what its buttons do; no module imports another in a circle; nothing keeps state between calls; exact versions are in `constraints.txt`. These rules are tests ([`tests/test_architecture.py`](tests/test_architecture.py)), and GitHub runs `ruff` and `mypy` beside them. The scripts that need openLCA now run in the tests against an openLCA made for them, which found two places where a failed step left objects in the database.
- [Nov 17, 2026] After v0.2.1, with the same model and results. The repository can now be operated and checked without its author: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) says where each idea of the paper lives in the code; [`docs/RUNBOOK.md`](docs/RUNBOOK.md) gives every task with the result to expect and the failures already met; `bash release.sh <version>` publishes a version and refuses when a check fails; [`tests/test_review.py`](tests/test_review.py) repeats the review on every push (numbers written by hand against the data, links, one version, no value of the licensed database); the names of the datasets left the code for a file per database, [`data/databases/`](data/databases/), with a guide for [another database](docs/BRING_YOUR_DATABASE.md); and `experiments/openlca/read_database.py` repeats, from the database file, what the paper says about the database. Also in the paper since v0.2.1: the third ablation of the proposal, the measured limit of the first order score, and the plan of a check of the probability against openLCA.
- [Nov 16, 2026] Release v0.2.1, with the same model and results as v0.2.0. The check against openLCA now removes the flows it creates, `experiments/openlca/clean_branch_objects.py` lists and removes what BRANCH wrote into a database, and the tests pass on Windows and on GitHub, so the Windows installer is built again.
- [Nov 16, 2026] Release v0.2.0, which corrects an error of the model. Versions 0.1.1 and 0.1.2 took a production mix of aluminium as the virgin metal beside a recycled content, and that mix already contains secondary aluminium, so the secondary metal was counted twice and the can and the foil of the carton looked better than they are. The virgin metal is now primary aluminium. One of the 18 central verdicts changes (refillable glass against the can in Brazil), and the paper gives the comparison before and after. I found the error by opening in the database each of the 70 datasets BRANCH uses; no other dataset is counted twice.
- [Nov 16, 2026] Experiments after a statistical review, on plans fixed before running ([`experiments/record/PLAN_2026-11-15.md`](experiments/record/PLAN_2026-11-15.md)): 30 cases of ten other pairs of packages (the one confirmatory test: fewer questions than uncertainty sampling, p = 0.016 over pairs), an equivalence test with the Sobol index of the impact (within a tenth of a question), a second kind of wrong expert, a second database (21 factors from ELCD 3.2), the Circular Footprint Formula, and an illustration on 100 synthetic models. With experts whose answers contradict the beliefs, 2.4% to 5.2% of the certificates of the 18 cases are wrong against a target of 2.5%: near the target and sometimes above it.
- [Nov 16, 2026] openLCA connector: the model BRANCH sends is now a native parametrised model. Every continuous choice is an input parameter, the amounts of the exchanges are formulas of those parameters, and an open choice carries its prior as uncertainty, so openLCA's own Monte Carlo simulation runs on it. Sending again updates the objects in place, aggregated datasets are linked by their default providers only, and nothing is written before you confirm a backup.
- [Nov 16, 2026] 27 European countries as regions with recycling rates from Eurostat, priors with their sources and a count of how much of each prior a source supports, and washing electricity widened to include the one published measurement.
- [Nov 16, 2026] The uncertainty that the database states for its datasets is not in the results: in the copy of BAFU:2026 I use, waste outputs carry a lognormal geometric mean of the opposite sign of the amount, the pattern GreenDelta confirmed as a database error for ecoinvent 3.9.1 in 2023, and a Monte Carlo simulation in openLCA then subtracts the treatment of waste. [`experiments/openlca/openlca_lognormal/`](experiments/openlca/openlca_lognormal/) has the check.
- [Nov 15, 2026] Release v0.1.2: PET and polyethylene now use the disposal datasets of their own polymer in BAFU:2026 (they had been using a plastics mixture), and expanded polystyrene uses its own incineration dataset. The whole benchmark and every validation against openLCA ran again; no verdict changed at the central values, and the mean number of questions in the chosen setting went from 2.75 to 2.87. The paper now names the stand-ins that remain (landfill of PET, the obsolete packaging glass datasets, the oil-fired plant in Brazil) and reports a larger run of 5,400 sessions for the certificate. A factor file extracted before this release needs the six new disposal factors: with openLCA open, `python experiments/openlca/extract_factors.py --method "EF 3.1" --update` reads only what is missing.
- [Nov 14, 2026] Release v0.1.1: installers for macOS (Apple silicon and Intel) and Windows with everything in this list: any product described by processes of the openLCA database, 15 materials, the search of the database and the automatic reading of missing factors. The page shows the version, and GitHub Actions now runs one whole comparison in each built app (version, questions, manager report) before it publishes the installer.
- [Nov 14, 2026] Any product, not only containers. A product can now be described by processes chosen from the openLCA database by name, one per life cycle stage, with an amount or the smallest and the largest amount when it is not known; BRANCH asks for the exact amount only if it can change the answer. The app searches the database, shows the unit of each process and reads its factor from openLCA on its own. Two example products that are not containers agree with openLCA to 4.7e-10 ([`paper/data/validation_any_product.csv`](paper/data/validation_any_product.csv)). The reports now name the split toxicity indicators (organics, inorganics) instead of repeating one name. One command uses the whole app against a real openLCA, from the search to "Send to openLCA": `python experiments/openlca/check_app_with_openlca.py` (all steps passed on 14 November 2026).
- [Nov 14, 2026] Eight more packaging materials as data files: polypropylene, polystyrene, expanded polystyrene, PVC, PLA, steel sheet (tinplate proxy), kraft paper and cartonboard, each with an example product in [`data/examples/`](data/examples). With corrugated board, the nine added materials were checked against openLCA for every dataset option in PT, DE and BR (42 products, largest relative difference 6.7e-9, [`paper/data/validation_new_materials.csv`](paper/data/validation_new_materials.csv)). Their recycling rates are assumptions, except for polypropylene (the national rate of all plastics) and, in Germany, for paper, board and steel. The app offers a material only when its factors are in the factor file; `python experiments/openlca/validate_materials.py` checks them against openLCA.
- [Nov 13, 2026] Experiments promised in the proposal, on a plan fixed before running ([`experiments/record/PLAN_2026-11-13.md`](experiments/record/PLAN_2026-11-13.md)): the chosen setting in three other impact categories (acidification, water use, fossil resource use) and two knowledge ablations (no location, uniform priors). Descriptive results in the paper, summaries in `paper/data/proposal_2026-11-13/`, one command to repeat them: `bash experiments/benchmark/run_proposal_experiments.sh`.
- [Nov 13, 2026] Corrugated board added as a material (`data/materials/corrugated_board.json`, example product in `data/examples/`); its German recycling rate is sourced, the default is an assumption, and its check against openLCA in a product system ran on 14 November (entry above). The connection panel of the app now lists the four steps before the first comparison and names the next one.
- [Nov 13, 2026] Paper: the discussion now states what BRANCH offers a small company (about three answers instead of 16 open choices and 10 to 21 linked exchanges per comparison, with every default visible) and what it cannot claim yet (no person outside the project has used it), and it lists the departures from the proposal. It also states that only Portugal, Germany and Brazil have national priors, and that the other electricity grids of the database run on default priors. `CONTRIBUTING.md` and `docs/lemma.md` point to the current files.
- [Nov 13, 2026] Priors checked against published values (`data/prior_checks.csv`, with a test). Two priors widened to include a published value: heat for washing, and the mass of the refillable glass bottle in Brazil. The aluminium foil of the carton has its own prior of recycled content.

- [Nov 13, 2026] Benchmark re-run with the national priors; paper, tables and figures rebuilt from it. The paper states where the human is in the loop (the base of the method) and where the human is in command.
